# ZXAJ 无人车三维仿真平台

基于程序化三维几何构建的 ZXAJ 四轮无人车研发演示台。包含机械结构展示、手动驾驶、虚拟传感器、二维导航、200 m × 200 m 园区和高密度三维 LiDAR 建图。所有遥测、传感器在线状态和摄像头画面均为本地仿真，未连接真实设备。

本次输入没有可读取的参考图片附件，模型依据文字描述制作，不代表对具体实车的尺寸测绘或照片级复刻。

## 启动

建议使用 Node.js 22.12 或更高版本，以及支持 WebGL 2 的现代桌面浏览器。

```powershell
npm.cmd ci
npm.cmd run dev
```

打开终端输出的地址，默认 http://localhost:5173/。端口被占用时 Vite 会选择其他端口。macOS/Linux 可使用 `npm`。

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

构建输出为 `dist/`，可以部署到静态文件服务器。首次安装需要网络；场景使用本地程序化模型、字体和材质，不依赖远程模型或 HDR 文件。

切到“导航与规划”，点击“规划路径”查看路线，再点击“运行”自动驾驶。默认目标为 `(7, -5)`。可以直接编辑目标坐标，或点击“起点”“目标”后在地面设置位置。起点必须满足碰撞与地图边界约束。

点击“障碍物”后在地面连续添加障碍物，再点击该按钮退出编辑。选择场景或列表中的障碍物，可以编辑 X/Z 或删除。目标和障碍物改变后，旧路线失效且车辆停止，需重新规划运行。遇到碰撞约束时控制器会停车，并在自主模式尝试重新规划；不可达原因显示在日志中。

手动控制和传感器模式会显示场景障碍物。数字样机模式初始隐藏障碍物，便于检查唯一车辆主体，但碰撞检测仍然生效。

底部支持日志过滤、清空、JSON 导出和当前运行时间线。时间倍率作用于仿真时钟与车辆运动；时间线显示运行进度，不提供历史回放。

## 园区与三维建图

默认打开数字样机展示。切到“园区建图”进入 200 m × 200 m 园区并启用三维扫描，再点击“开始建图”累积地图。园区包含连通道路、十字路口与支路、路缘与人行道、不同高度的建筑及门窗入口、树木、路灯、标志、停放车辆、围栏和隔离桩。道路、建筑和设施由配置生成，重复物体按 50 m 区域、形状和颜色分组实例化，在各批次内复用几何和材质，并进行视锥裁剪。

使用原有驾驶按钮或键盘沿道路探索。“返回无人车”恢复驾驶视角并启用跟随；“自由观察”关闭跟随；“俯视地图”观察整个园区。直接拖动相机可中止视角过渡。大型建筑、墙体、树干、车辆等实体参与碰撞和二维规划；隐藏原始环境仅影响显示，不移除扫描与碰撞几何。切换环境或修改障碍物会清空旧地图，防止混用不同场景的点。

| 参数 | 默认值及范围 |
| --- | --- |
| 水平扫描 | 360°，角分辨率 0.4°，可调至 0.2° |
| 垂直扫描 | 64 线，可选 32 / 64 / 128；视场角默认 40°，范围 10°～90° |
| 探测距离 | 默认 60 m，范围 10～100 m |
| 扫描频率 | 目标 5 Hz，可调 1～10 Hz；实际频率受设备性能限制并单独显示 |
| 单次射线 | 默认 57,600 条，最高 230,400 条；未命中不生成点 |
| 地图体素 | 默认 0.1 m，范围 0.05～0.3 m；修改时清空地图 |
| 点尺寸 | 实时层与地图层独立调节 |
| 颜色 | 单色、高度、距离、模拟反射强度 |

“暂停建图”只停止累积，实时扫描继续；顶部“暂停仿真”同时冻结车辆和扫描。“清空地图”清除历史点和位姿记录；“重新开始建图”清空并启用扫描与累积。实时层、历史层、原始环境、扫描范围和历史范围可分别显隐。关闭 LiDAR 清除实时点但保留历史地图。

扫描在独立 Worker 中通过 BVH 加速，对与渲染共享的长方体、圆柱和椭球表面进行几何求交。每次扫描保存传感器位姿，通过四元数将局部点转换到世界坐标，使用体素去重累积。渲染使用固定容量 `BufferGeometry`、动态属性及局部更新，不为每个点创建 Mesh。一次最多执行一个扫描任务，旧配置或暂停前的过期结果被丢弃，处理速度不足时不会无限排队。

地图最多保留 400,000 个体素代表点，容量满后按 FIFO 回收旧体素；位姿历史最多 256 次。实时点、地图点及渲染位置/颜色的 CPU/GPU 缓冲估算约 42.9 MB。此值不包含 JavaScript 体素索引、Worker、传输临时数组、场景和浏览器开销，不代表进程总内存。历史范围记录自清图以来的覆盖范围，FIFO 回收后不会缩小。

UI 明确标为“仿真位姿建图”：定位来自仿真器精确位姿，不包含扫描匹配、回环检测或真实 SLAM 定位。强度是按场景表面反射率生成的模拟值。`SLAMAdapter` 提供未来接入位姿估计系统的接口，当前实现为仿真位姿直通。

## 三维模型与坐标

- 使用米、秒、弧度作为内部单位；界面角度显示为度。
- Y 轴向上；车辆零航向朝 +X，正航向转向 +Z。
- 车身长 2.8 m、宽 1.64 m，轴距和轮距均为 1.95 m，轮胎半径 0.43 m。
- 车身尺寸、运动参数、地图和传感器参数集中在 `src/config/roverConfig.ts`。机械组件内保留局部安装偏移，修改车型比例时也需同步检查这些偏移。
- 碰撞圆由底盘和包含胎纹、轮毂余量的车轮外包络计算，半径约 1.86 m；规划额外增加 0.12 m 安全余量。
- 数字样机地图范围为 X/Z 各 -10 到 10 m，A* 网格分辨率为 0.5 m；园区范围为各 -100 到 100 m，分辨率为 2 m。环境尺寸和道路布局集中在 `src/environment/EnvironmentConfig.ts`。

模型包含带悬架避让缺口的多层底盘、侧面 ZXAJ 标识、四个独立胎纹车轮、八辐轮毂、八个齿轮、旋转雷达和蓝青色指示灯。齿轮按齿数比转动，车轮按行驶距离转动。

第二轮升级保留原有车型比例和操作流程，细化以下结构：

- 四组独立悬架：有厚度的上下叉形控制臂、转向节、底盘固定座、斜撑、连接轴、减震器外筒、抛光活塞杆、橡胶防尘套、弹簧及上下安装环。减震器具有随速度变化的小幅压缩动画。
- 摄像头总成：底部基座、双侧带减重孔的承力板、三角斜撑、固定横梁和轴承支撑旋转横梁。保留四组主摄像头（前三目和上层单目）及两枚保险杠镜头，各主摄像头带外壳、镜筒、镜片、独立调节座、紧固件与线缆。前三目总成支持 ±35° 水平旋转。
- 局部外壳：分段侧面电子舱护板、上层罩壳、后部舱盖和前部保护面板，带真实贯通的散热槽及安装螺栓。完整模式仅安装这些局部护板，继续暴露主要机械结构；透明模式使用低透明度材质、关闭深度写入并调整绘制顺序。
- 材质区分铝合金、深色金属、紧固件、橡胶和镜片；场景通过本地程序化环境光源提供金属反射。

`mechanicalConfig` 集中配置底盘避让轮廓、悬架安装点、减震器两端、弹簧、摄像头支架、外壳厚度和倒角；`materialConfig` 配置材质；`detailProfiles` 定义两档几何与渲染精度。各独立板件的安装位置和尺寸位于对应装配组件中，修改车型后应同时检查装配间隙。

`rover/geometry.ts` 提供实际使用的板件、叉形支架、齿轮、螺旋弹簧、圆角面板、镜头外壳和紧固件工厂。静态几何通过 `useGeometry` 按完整参数缓存并引用计数；延迟释放适配 StrictMode 与同帧重挂载。共享几何的网格禁用自动释放，由缓存管理资源所有权；共享材质在车辆根节点卸载后释放。胎纹使用 `InstancedMesh`，档位变化与卸载时释放实例缓冲。逐帧动画只更新对象变换，不重建几何。

技术栈：React、TypeScript、Vite、Three.js、React Three Fiber、drei、Zustand、Tailwind CSS、Lucide React、Vitest。布局和控件的精细样式位于 `src/styles.css`。

`VehicleController.updateSimulation(delta)` 是统一更新入口。它将时间增量分步处理，使用可变运行态驱动逐帧动画，以约 10 Hz 的仿真时间频率向 Zustand 发布遥测，避免每帧更新 React 页面。

`MotionModel.stepMotion` 接收 `VehicleState`、`ControlInput`、时间步长与速度上限，返回下一状态。`PathPlanner.planPath` 接收地图、起终点、障碍物和安全半径，返回路线、访问格数及失败原因；它独立于 React 和 Three.js。

`SensorPlugin<T>` 定义 `id` 与 `sample(vehicle, obstacles, time)`。当前 `SensorSimulator` 实现雷达和超声波组合模块。新增传感器可以实现该接口，并在控制器中组合调用、扩充状态和面板；当前没有自动插件发现机制。

新增控制算法可替换运动或路径跟踪函数；新增规划算法可保留现有输入输出契约。GLB/GLTF 接入点是独立的 `RoverModel` 渲染层，当前未实现文件上传或外部模型导入界面。

## 验证

Vitest 共 49 项测试：16 项仿真测试覆盖加减速、倒车转向、帧率一致性、车轮行程、转向安全包络、碰撞、射线、传感器阈值、A* 障碍物膨胀、不可达目标、非网格端点、导航到达、暂停、急停锁定、场景编辑失效和慢帧分步；9 项模型与状态测试覆盖几何有效性、贯通孔槽、控制臂和底盘避让、摄像头轴承在旋转范围内的支撑、减震器安装、性能档位几何精简以及显示切换和复位时的状态保留。另有 24 项测试覆盖园区连通性与碰撞、三种几何求交、360° 多线扫描、遮挡和量程、姿态与世界坐标、重复扫描稳定性、体素去重、容量回收、清图及位姿历史上限。

## 当前限制

- 手动驾驶采用简化自行车运动学；自主导航可以先原地调整朝向再沿路径运动，不模拟真实车辆的最小转弯半径。
- 采用保守二维碰撞圆，无真实刚体、轮地接触、摩擦或悬架受力求解。悬架与 IMU 姿态是运动驱动的展示动画。
- 传感器页保留的辅助雷达为 120 条二维射线、7 m 量程；超声波为前向三条二维射线，均依据障碍物平面轮廓检测。“园区建图”的独立三维 LiDAR 对共享长方体、圆柱和椭球表面求最近交点，考虑高度与几何遮挡，但未模拟测距噪声、光学材质响应或真实传感器精度；曲面渲染使用有限分段网格。
- 建图采用仿真精确位姿，不包含真实 SLAM 定位、扫描匹配与回环检测。高密度扫描的实际频率受设备和场景负载限制，本机软件渲染测试未达到默认目标 5 Hz。
- 摄像头提供独立车载视角，不提供双目深度、图像识别或视频编码。
- 未接入 ROS/ROS 2、MQTT、WebSocket 或真实硬件；未实现会话持久化和历史回放。
- Three.js 与场景代码的生产包较大，Vite 可能给出 chunk 大小提示。构建可完成；后续可以按工作区拆包并优化重复几何与绘制调用。
